# SD bundle contract

The head-unit controller retains the `mhi2` bundle directory and `PICOSD_*` wire protocol for compatibility with existing SD cards.

Every bundle needs `start.sh`, `stop.sh`, and a strict v1 `manifest.json` generated by `make_sd_bundle.py`. Maximums: 32 files, 1 MiB per file, 8 MiB total, 16 KiB manifest. Paths must be relative and contain only the supported ASCII path characters. Symlinks are rejected. Hashes and sizes are checked after copying into RAM.

A manifest may target the SHA-256 of the unit's original JXE (`--firmware HASH`) or use `any` for scripts reviewed to be firmware-independent. The selection digest identifies the exact manifest. A changed card is not silently trusted for auto-run.

Scripts receive the runner's RAM workspace in `MHI2_RUN_DIR`. Keep background workers and their state there. `start.sh` must return within 180 seconds; long-running work should start a bounded worker and return. `stop.sh` must stop its workers and clean up within 30 seconds. Script output is bounded to 64 KiB; the Pico exposes a bounded recent log. The controller treats cleanup failures separately from successful stop; do not infer cleanup solely from loss of Wi-Fi.

The runner itself stages under `/ramdisk/pico-manager`, not a persistent installation location. A script is still an arbitrary privileged program and may modify persistent HU files if written to do so.

## Optional storage progress

A worker may atomically replace `/ramdisk/pico-manager/progress` with a single ASCII line:

```text
v1 PHASE SOURCE COPIED CHECKED VERIFIED TOTAL PART PART_DONE PART_SIZE ELAPSED_MS SEQUENCE
```

Supported phases: `preparing`, `copying`, `verifying`, `complete`, `failed`, `cancelled`, `cleanup-required`.
Supported sources: `none`, `mmx-emmc`, `mmx-nor`.
All counters are nonnegative decimal integers. Use monotonic elapsed milliseconds and sequence numbers. Write to a temporary file, then rename it over `progress`; do not update a partially visible line in place.

The manager validates the record, forwards it in `/manage/status`, and reports sample/heartbeat ages. Invalid records do not become shell commands or page HTML. The UI models copy plus verification as two equal phases and reaches 100% only on a validated `complete` record. Generic payloads can omit this file and report textual logs instead.

The example bundle is a RAM-only demonstration, not an Android Auto mod or a storage dumper. Existing reviewed bundles can be managed without putting them into this firmware repository.
